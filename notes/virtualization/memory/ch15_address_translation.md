## Ch15: Address Translation
### Summary:
Similarly to the way the OS virtualizes the CPU, the OS virtualizes memory by making heavy use of hardware support. This is to serve the goal of presenting a simple interface to the process requesting memory while preventing processes from accessing memory allocated to other processes and without slowing down access to memory. 

This is accomplished by using a base and bounds register on the MMU of the processor. The MMU translates load and store requests from virtual memory addresses to physical memory addresses by adding the base register. In the case that a virtual memory address exceeds the value in the bounds register, the MMU executes a trap instruction that calls the exception handler for invalid memory access. It is the responsibility of OS to set the base and bounds registers when starting a process or performing a context switch.

This approach works well given these assumptions: all processes want to use the same amount of memory, the amount of memory that a process wants to use is fixed, all processes want to use less memory than there is physical memory, the physical address space of a process is contiguous. 
### Terms:
- physical address:
    - memory address generated by the hardware after address translation
    - allows the cpu to actually access memory
- virtual address:
    - memory address used by the software to access the abstraction of memory before memory address translation
- hardware based address translation:
    - the physical hardware transforms the address of a requested piece of memory from the place that the program thinks that memory is to the place that memory actually is
    - the hardware is instructed by the OS in terms of which portions of the logical address space map to which portions of the physical address space
- starting assumptions:
    - the users address space is contiguous in physical memory
    - the size of the users address space is smaller than physical memory
    - each address space is exactly the same size
- base and bounds / dynamic relocation:
    - the base register is the offset from zero at which the address space of the memory alloted to this process starts
        - physical address = virtual address + base
    - the bounds register is the highest virtual memory address that the program should be able to access 
    - trying to access an address higher than the bound results in a crash of the process
    - the base and bounds registers should only be able to be changed by the kernel
        - this is enforced at the hardware level by requiring that the permission bit on the CPU is set
        - the permission bit on the CPU is set by trapping into the kernel code
    - the base an bounds registers should be saved and restored for the respective processes during a context switch
    - this functionality requires that the CPU hardware has the ability to:
        - set the base and bounds registers in privileged mode
        - translate addresses from virtual addresses to physical addresses
        - detect out of bounds addresses
        - register exceptions in privileged mode
        - raise exceptions
- cleanup:
    - when the process finishes, the os must modify any internal structures which maintain metadata about that process to reflect that it finished
        - memory free list
        - process control block
